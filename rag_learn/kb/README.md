# PDF 知识库问答

> 丢一个 PDF 进去，然后用自然语言问它 —— 答案带**引用来源**，追问能听懂上下文。

一个从零手写的 RAG（检索增强生成）系统：前 6 天把每一步的原理和坑都手搓过一遍，
第 7 天组装成一个能用的项目。

## 它是什么

- **上传 PDF → 自动建索引**：逐页切块、贴"身份证"（文件名/页码/字符偏移）、向量化、存进 Chroma
- **多轮追问**：问"它是给零基础的人看的吗？"，系统先把它消解成"「某本书」是给零基础的人看的吗？"再检索
- **答案带引用来源**：`（依据：sample20.pdf 第7页）` —— 不是装饰，是让答案**可验证**
- **两种入口**：命令行（`cli.py`）和 HTTP 接口（`server.py`），核心逻辑共用同一套

## 架构

```
【离线索引 · ingest.py】  提问之前跑一次，可以慢慢跑

    PDF ──▶ 逐页读文本 ──▶ 切块(400字符/重叠80) ──▶ 贴身份证 ──▶ 批量向量化 ──▶ 存入 Chroma
             pypdf          split_overlap          source/page     智谱embedding      持久化
                                                    /start_index   (单次≤64条需分批)

                                              │
                                              ▼  向量 + 文本 + 身份证
【在线查询 · qa.py】  每问一次都要走一遍
                                              │
    用户提问 ──▶ 指代消解 ──▶ 向量化 ──▶ 检索top5 ──▶ 距离→相似度 ──▶ 拼prompt ──▶ LLM生成
                 (LLM改写)   智谱      Chroma       1-dist降序      资料+规则       DeepSeek
                    ▲                                                   ▲
                    │                                                   │
              对话历史 ────────────────────────────────────────────────┘
              （消解用、也让模型知道"它"指什么）
```

**两条流水线的意义**：离线那半段慢一点没关系（可以批处理）；在线那半段的每一毫秒，
用户都在等。所以"换一个更强的 Embedding 模型"要**重建整个索引**，而"换一个更强的生成
模型"只改一行配置。

## 快速开始

```powershell
cd D:\Desktop\Practice\rag_learn

# 1. 装依赖（只有第一次，约 400MB）
.\.venv\Scripts\python.exe -m pip install -r requirements.txt

# 2. 配密钥：把 .env.example 复制成 .env，填进你自己的 key
#    LLM_* 对话用 DeepSeek   /   EMB_* 向量用智谱

# 3. 建索引：把一个 PDF 喂进去（这一步会真的调 Embedding API）

#    预期输出：✅ 索引完成：pdf_kb  页数=20  块数=69

.\.venv\Scripts\python.exe -X utf8 kb\cli.py
```

问答时的内置命令：`/clear` 清空对话历史、`/exit` 退出。

其他命令：

```powershell

.\.venv\Scripts\python.exe -X utf8 kb\cli.py reset     # 清空集合（重新索引时用）
```

## HTTP 接口版

```powershell
# 方式 1（推荐，在哪个目录跑都行）
.\.venv\Scripts\python.exe -X utf8 kb\server.py

# 方式 2（要热重载就用这条，但**当前目录必须是 rag_learn**）
.\.venv\Scripts\python.exe -X utf8 -m uvicorn kb.server:app --reload --port 8000
```

启动后打开 **http://127.0.0.1:8000/docs** —— FastAPI 自动生成的交互式文档，可以直接点着试。

| 接口 | 作用 |
|---|---|
| `GET /stats` | 知识库状态（块数、来源分布） |
| `POST /upload` | 上传 PDF 并建索引（表单文件） |
| `POST /ask` | 提问，可选带对话历史，返回答案 + 引用来源 |
| `POST /ask/upload` | 上传并立刻提问（一步到位） |

### 起服务报错？先看这里

**症状 1：闪一下就退出，看不到报错**

在 **VS Code 的终端（TERMINAL）里**跑，不要用 ▶ Run 按钮（窗口一关报错就没了）。
另外确认解释器是 **`rag_learn\.venv\Scripts\python.exe`** —— 工作区里还有别的 venv，
选错了会报 `ModuleNotFoundError: No module named 'httpx'`。

**症状 2：`[Errno 10048] 每个套接字地址只允许使用一次`**

8000 端口被上一次没关干净的服务占着（`--reload` 模式会 fork 子进程，Ctrl+C 常杀不干净）：

```powershell
# 看谁占着
Get-NetTCPConnection -LocalPort 8000 -State Listen
# 一键清掉所有残留的本项目服务
Get-CimInstance Win32_Process -Filter "Name='python.exe'" |
  Where-Object { $_.CommandLine -like '*uvicorn kb.server*' } |
  ForEach-Object { Stop-Process -Id $_.ProcessId -Force }
```

## 关键设计决定

这几条都有**实测数据**支撑，不是拍脑袋：

**① 为什么按页切，而不是把全文拼起来切？**
因为**溯源需要边界**。一块如果横跨第 5、6 两页，`page` 该写几？写 5 就漏了 6。
代价是跨页的语义会被切断 —— 实测：按页切得 69 块，全文切只有 61 块，
多出来的 8 块就是被页边界切碎的"页尾碎片"。
**这是取舍不是对错**：我们在意"能不能给出引用"，所以选了按页切。
（官方入门教程的 `split_documents` 也是按页切的。）

**② 为什么 `chunk_size=400, overlap=80`？**
小块的语义更聚焦、检索更准，但**语义可能不完整**；大块上下文全，但**向量被平均掉**、
还更贵。实测对比过 `200/40`、`400/80`、`800/160` 三组：小块（200）在三道测试题上
全部命中正确来源，400 命中 1 道，800 命中 2 道。
但**只用了 3 道题就下结论是不可靠的**（单次对比毫无意义），所以先保守取 400 ——
要系统调参得用第 5 天那套 15 题的评测集。

**③ 为什么 Chroma 要显式写 `hnsw:space="cosine"`？**
因为**它默认是 l2 欧氏距离，不是余弦**。实测：同一条查询，默认库返回 `dist=0.9180`，
设了 cosine 的库返回 `dist=0.4590`（正好 = 1 − 0.5410，而 0.5410 就是手写余弦算出的相似度）。
⚠️ 还要注意**它返回的是距离不是相似度，越小越像** —— 必须换算成 `1 - dist` 并**降序**排，
否则喂给模型的资料是**从最不相关开始**的，而且程序不会报错。

**④ 为什么要先做指代消解？**
用户第二句问"那它的成本高吗？" —— **"它"在向量空间里没有任何意义**，
直接拿这句话检索会捞回一堆无关内容。对照实验（同一段 3 轮对话跑两遍）：

| | 检索命中的来源 |
|---|---|
| 不消解 | **0 / 2**（第 2、3 轮全错） |
| 消解后 | **2 / 2** |

第 3 轮的差距最能说明问题：不消解时只捞到无关的 PDF、答"资料中没有提到解决办法"；
消解后捞到正确来源，直接给出了答案。
**注意：检索用消解后的独立问题，但生成时还要把对话历史给模型** —— 两件事目的不同
（检索要语义，生成要连贯）。

**⑤ 引用来源是怎么实现的？**
`source`/`page`/`start_index` 这三件套跟着每个块**一路带下来**：
切块时贴上去 → 存进 Chroma 的 metadata → 检索时取回来 → 拼 prompt 时渲染成人话
（`[来源：sample20.pdf 第7页]`）→ 模型才有可能在回答里引用。
⭐ 关键坑：**框架不会自动帮你做这件事** —— 用 LangChain 的 `add_texts` 时如果不传
`metadatas`，检索回来的 Document 就是"裸的"，取来源直接 `KeyError`。

**⑥ 检索参数是怎么定的？**（15 题测试集，13 题正样本 + 2 题"语料里没有"）

| k（召回条数） | 命中率 |
|---|---|
| 3 | 80% |
| **5** | **87%** |
| 10 | 87%（**没有额外收益**） |

| 相似度阈值 | 命中率 | 平均保留块数 |
|---|---|---|
| 不过滤 | 87% | 5.0 |
| **0.35** | **93%** | **4.3** |
| 0.40 | 87% | 3.1（开始伤正样本） |

**阈值 0.35 是"免费的午餐"**：命中率**反而涨了 6 个点**（因为"语料里没有"的问题被正确
过滤空了，系统这时才该说"资料中没有提到"），同时每次少喂 0.7 块 —— 又准又便宜。

## 已知限制

诚实说明，免得你踩坑：

- **目前只支持 PDF**。TXT / Markdown 需要扩展 `ingest.py`（`chunk_pdf` 复用的是
  Day3 的通用切块函数，加格式不难）
- **只支持有文字层的 PDF**。扫描件/图片页抽不出文本（实测样本里就有两页只有 73/83 个字符），
  会产生低质量块 —— 真实场景需要接 OCR
- **全量重建索引**。没有增量更新：换一个 PDF 或改一次参数，得 `reset` 后重新索引
- **没有 rerank**。精排（用更强的模型对候选块重新打分）能显著提升精度，本项目没做
- **阈值 0.35 是在 15 题上试出来的**，样本偏小，换语料需要用第 5 天那套评测集重新标定
- **没有并发控制**。Chroma 单机嵌入式模式，多人同时上传/索引没做保护
- **没有鉴权**。`server.py` 是本机自用，直接暴露到公网等于把 API 额度送人
